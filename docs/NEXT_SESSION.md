## Decisions

The §19.4 confirmations (D1, D3, D4, D5, D11, D9, D16) were presented on 12 September 2026 and not overridden, so the proposals stand. The user can still change them; SPEC §1 lists what each override touches.

M1 recorded one deviation in `generate.ts`: §7.2's literal rule yields about 80 % new minutes, contradicting AT-09's 50–70 % window; `pickTarget` draws the remainder from the level's other allowed minutes (about 60 %).

M2 decisions worth knowing:

- The prize grant happens on the S5 button press (`choose` immediately followed by `apply` or `keep`), not on tile selection, so the child can change the selection freely; a reload on S5 shows the same pair with nothing granted (AT-30). The previous handoff said "`mission/choose` on selection"; that would have made the first tap final.
- The Hint button is never disabled while a puzzle is open (only pressed), so keyboard focus is not dropped to the body.
- `ChoiceGroup` uses plain Tab order plus arrow keys (no roving tabindex); when a focused option becomes disabled, focus moves to the next enabled option.
- The MATCH hint shows "long hand → 12" for whole hours (the hand position), not "→ 0".
- The READ hint counter animates the number inside the translated `hint.minutes` sentence (the number is located in the interpolated string, not concatenated).
- Not built in M2: the story reaction after puzzle 4 (rocket launch / tea party before S5), sounds, `SidePanel` and `HoldButton` (needed from M3/M4), the "New" badge (no save field yet).
- Fixed in M0 code: the S0 title no longer steals focus from the first-launch language dialog.

## Context to retain

- The child is seven and already reads whole hours. Defaults: Reading R2 (half hours), Elapsed E1 (whole-hour gaps).
- 14:30 → 19:15 = 4 hours 45 minutes, distractors 4 h 15 min and 5 h, jumps +4 h → 18:30, +30 min → 19:00, +15 min → 19:15; guaranteed as puzzle 4 of each theme's first completed E3 mission (`progress.firstE3Done` is set on completion, not on start).
- Hour hand moves continuously (3:30 → 105°). No timers, lives, penalties, purchases, ads, analytics or accounts.
- `core/` must stay free of DOM and Preact imports (enforced by ESLint). Every state change goes through `dispatch`; UI-only state (wrong picks, open panels, selections) lives in component state keyed by `mission.index` so it resets per puzzle.
- All animations are CSS and read `data-motion` on the stage; the only JavaScript-driven animation is the SET clock drag. Pointer handlers in `SetClock` read live values from refs.
- Playwright runs against the production build (`npm run build && vite preview`), so dev aids (`?seed`, `?screen`, `?lang`, harness) are unavailable in e2e; tests read the autosaved save from localStorage. Autosave is debounced 250 ms and flushed on `pagehide`, so `page.reload()` is safe but reading localStorage right after a click needs `expect.poll` (see `flow3-keyboard.spec.ts`).
- The in-app Browser pane sends synthetic key events that do not activate buttons; verify keyboard behaviour with Playwright, use the pane for visual checks (its screenshots can lag a second behind the DOM).
- Stage layout is 1536 × 1024; the mission panel is 1000 × 860 at (268, 80). In 24-hour reading mode the READ layout with the period badge fills the panel almost completely; any taller content needs a smaller clock or a shorter footer.
- Not yet implemented and left for M3/M4: the progression suggestion streak (`progress.suggestion`, §7.1) is never updated; sounds (§15.4); S6 Parent corner (levels lock has no UI yet, AT-29 is implemented on S2 but untested end to end); Sweet art; the story reaction after puzzle 4.
- SPEC §7.2 vs AT-09 discrepancy (see Decisions) is worth raising with the user when convenient; the code comment in `pickTarget` explains the choice.
