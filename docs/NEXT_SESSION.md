## Decisions

The §19.4 confirmations (D1, D3, D4, D5, D11, D9, D16) were presented on 12 September 2026 and not overridden, so the proposals stand.

M1 recorded one deviation in `generate.ts`: §7.2's literal rule yields about 80 % new minutes, contradicting AT-09's 50–70 % window; `pickTarget` draws the remainder from the level's other allowed minutes.

M2: the prize grant happens on the S5 button press; the Hint button is never disabled; `ChoiceGroup` uses plain Tab order plus arrow keys; the MATCH hint shows "long hand → 12" for whole hours.

M3 decisions worth knowing:

- Focus after closing a panel returns to that panel's own button (Decorate or Dress up), not to whatever had focus when the D / W key was pressed; both are "the opener" and the button is the predictable target for a child on the keyboard.
- Reactions run in free play and in dress-up mode, never in decorate mode (there a slot click places). The heroine and Pip get `pointer-events: none` in decorate mode so they never block the rug slot they stand on.
- The toy rocket plays its wobble first and opens S2 on `animationend` (or after 900 ms); the M key and the "Choose a mission" button go straight to S2.
- Keyboard placement uses `event.detail === 0` on the tile's click to tell Enter/Space from a mouse click; the mouse arms the tile, the keyboard places at once (each slot type has exactly one slot).
- Generated full-frame art stays at its native 1536 × 1024 rather than being upscaled to the 3072 × 2048 "2×" target: upscaling adds bytes without detail (the room is 502 KB, under the 1 MB guideline).
- `SidePanel` is not modal: the room stays clickable because decorate mode places by clicking a slot; Tab is not trapped.
- The "New" badge lives in the save (`newItems`) rather than being derived, so "earned and never placed or worn" survives swaps back to starters.
- Nunito is served as Google's variable subsets (one file covers weights 700–900); body text is 700 because the child-facing UI is bold throughout.

## Context to retain

- The child is seven and already reads whole hours. Defaults: Reading R2 (half hours), Elapsed E1 (whole-hour gaps).
- 14:30 → 19:15 = 4 hours 45 minutes, distractors 4 h 15 min and 5 h, jumps +4 h → 18:30, +30 min → 19:00, +15 min → 19:15; guaranteed as puzzle 4 of each theme's first completed E3 mission (`progress.firstE3Done` is set on completion, not on start).
- Hour hand moves continuously (3:30 → 105°). No timers, lives, penalties, purchases, ads, analytics or accounts.
- `core/` must stay free of DOM and Preact imports (enforced by ESLint). Every state change goes through `dispatch`; UI-only state (wrong picks, open panels, armed tile, ghost, running reaction) lives in component state. Reactions dispatch nothing except `inventory/lamp`.
- All animations are CSS and read `data-motion` on the stage; the only JavaScript-driven animation is the SET clock drag. Reactions end on `animationend` (with a 2.5 s fallback timeout), which also fires immediately under reduced motion.
- Playwright runs against the production build (`npm run build && vite preview`), so dev aids (`?seed`, `?screen`, `?lang`, `?debug`, harness) are unavailable in e2e; tests seed or read the save in localStorage (`mcr.save.v1`). `tsc -b` type-checks `e2e/` with the Node lib only (no DOM types): pass browser code to `page.evaluate` as a string or keep it in helpers. A key press that must reach a listener registered in a `useEffect` can arrive before the effect runs after a render; keep window listeners registered once and read state through refs (see `S1Room`), and in tests wait for the focus the UI sets itself (`toBeFocused`) instead of forcing it. Autosave is debounced 250 ms, so reading localStorage right after a click needs `expect.poll`.
- The in-app Browser pane sends synthetic key events that do not activate buttons and does not fire focus events while its window is unfocused; verify keyboard behaviour with Playwright, use the pane for visual checks (its screenshots can lag a second behind the DOM, take two).
- Stage layout is 1536 × 1024; the mission panel is 1000 × 860 at (268, 80); the side panel is 440 px on the right and the room scales by 0.7135 from its left-centre while a panel is open. Assets are at 2×: stage size = asset px ÷ 2 × slot scale.
- Codex CLI (`/Users/emret/.local/bin/codex`, 0.153.4) generates through `tools/gen-assets.ts`; presets astra-light = `gpt-6-astra` low, sol-med = `gpt-5.6-sol` medium; about one minute per asset; raw PNGs in `assets/.gen/` are committed, `.log` / `.last.md` are not. The generated images have plain white backgrounds; `post-assets.ts` flood-fills from the borders (threshold 236) so white areas inside an object survive. Never regenerate `approved` entries; never mark entries `approved` yourself.
